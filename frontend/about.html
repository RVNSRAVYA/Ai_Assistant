SmartCode AI System Documentation

A comprehensive overview of the problem statement, proposed solution, system architecture, and evaluation guide.

⚠️

Problem Statement

Computer science students frequently face steep learning curves when transitioning to programming. Common hurdles include:

  • Cryptic compiler errors and runtime exceptions without actionable context.
  • Difficulty translating algorithmic concepts (e.g. recursion, loops, OOP) into working syntax.
  • Complexity of setting up local development environments and toolchains.
💡

Proposed Solution

SmartCode AI provides a unified web-based coding assistant and execution workbench that combines:

  • A multi-mode pedagogical AI assistant (Generate, Explain, Debug, Q&A).
  • An integrated browser-based Monaco editor with multi-language syntax highlighting.
  • Safe, isolated remote code execution with custom standard input (stdin) support.

🏛️ System Architecture

SmartCode AI follows a clean, decoupled client-server architecture designed for high scalability, rapid response times, and complete server security.

⭐ Key Project Advantages

Beginner Friendly

No complicated setups. Students can generate, test, and debug code immediately in their browser.

Safe Isolated Execution

Configurable AI Engine

Switch easily between Google Gemini, Groq, OpenAI, or smart offline demo mode via environment variables.

🎓 Project Review & Viva Q&A Guide

Prepared answers to common questions asked by college examiners and project reviewers:

Q1: Why did you choose FastAPI over Flask or Django?
FastAPI is modern, extremely fast (powered by Starlette and Pydantic), provides automatic OpenAPI/Swagger documentation, and includes built-in asynchronous request handling with clean type hints.
Q2: How is arbitrary code execution secured?
Arbitrary code is never executed directly on the host server. The backend forwards execution requests to an isolated Piston sandbox container with strict CPU, memory, execution timeouts (5s), and process isolation.
Q3: How are API keys protected from client-side exposure?
All AI API keys and third-party credentials reside strictly on the backend server within a protected .env file. The frontend client only interacts through authenticated backend REST endpoints.
Q4: What are the planned future enhancements?
Future versions will incorporate user authentication, personal question history, real-time peer code collaboration, voice input for accessibility, and automated unit test generation.
